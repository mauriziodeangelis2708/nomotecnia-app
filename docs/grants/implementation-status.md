# Configurable grant studio — development checkpoint, 16 October 2026

This is an unfinished development feature, not a production release or a replacement for the audited Lazio assessment. Production remains on merge 699b0fa077503b13f95eba62d0547003c3491b2e.

## Implemented

- Data-only, versioned definitions for questions, conditional visibility, eligibility/exclusion, documentary requirements, score and grant expressions. No eval, executable templates, provider tools, or raw HTML rendering.
- Strict schema validation, bounded nesting/size, reference/type checks, conservative unknown answers and numerical-error handling. Hidden stale answers are excluded. All requirements need exact, normalized page quotations that exist in the supplied source.
- Admin studio for local PDF extraction/OCR, explicit text submission to a generation endpoint, draft review, per-page and per-item confirmation, independent expected test scenarios, questionnaire/result preview, save and publication.
- Immutable activated versions; creation of a new version resets review. Assessment and report reference the activated version UUID. Database trigger prevents subsequent version changes, including through another editor.
- Staging-only grant_templates migration, admin-only writes, member access to activated versions, no customer/anonymous access. Existing assessment/client RLS remains in force.
- Same-origin generation gateway authenticates the user against Supabase Auth and queries actual admin roles. It accepts structured model output only, restores caller-supplied source/identity metadata, rejects hallucinated citations, and never publishes the output.
- Feature flag VITE_ENABLE_GRANT_STUDIO is off by default. Model calls require both an AI binding and server BANDO_GENERATOR_ENABLED=true. Neither has been enabled in production or staging.

## Requirement inventory prototype and conditional-source guard — 2026-10-16

A separate first model call extracts a bounded, cited requirement inventory before seeing any draft. Generation receives that inventory plus a provider-side JSON Schema for predicates, formulas, rule variants and explicit coverage mappings. Local validation remains authoritative; there is no syntactic repair. Model-only inventory is capped at 40 entries/16000 serialized characters; deterministic conditional-paragraph guards can add entries up to 80 under the same size cap. The original excerpt is not truncated. Three model calls share the existing 90-second request deadline; this is not a proven deployed latency path.

Optional definition.requirements persists IDs, labels, source citations, linked question/rule IDs and unresolved gap text. Missing mappings become gaps. Unknown/duplicate mappings or nonexistent targets fail validation. Merge remaps links through question/rule deduplication and retains each requirement separately. The admin review list displays the inventory and requires a separate checkbox for each item. Both lifecycle validation and the staging database reject publication with gaps, empty coverage, missing links or unreviewed inventory items. Existing definitions without inventories remain compatible. Clearing the general unresolved list does not clear inventory gaps. Human operators must resolve/review the actual definition, not accept the model's assurance.

Real evidence on complete Avviso pages 4 and 5 (not the full package): the constrained inventory call returned eight items with exact citations, but still omitted essential exceptions and grant amounts. It consumed 255.41439819335938 neurons. The deterministic guard independently preserves complete source paragraphs containing a meno che / ad eccezione / a condizione che / fermo restando / purché / salvo; such entries always receive a manual gap even if the model supplies links. It is a conservative lexical safeguard, not a complete legal parser; implicit/other-worded exceptions and cross-page context still require human review. Oversized paragraphs/inventories fail rather than truncate.

A subsequent real generation using this inventory and provider JSON Schema returned supported operators and required condition fields, but still produced self-gated eligibility (when equal to condition) and an inverted previous-beneficiary exclusion. The new strict validator rejects self-gated eligibility because a negative answer would otherwise skip its own requirement. It consumed 670.7892456054688 neurons.
